# Agent Efficiency 0.2.2

Release: `v0.2.2`, dated 2026-11-06. The owner approved publication after
local validation. Live installation and migration checks remain separate.

## Changes

- Tool calls reported through several host events count once. Separate
  success and failure results remain distinct when identical calls finish
  in a different order.
- Doctor reports each installed plugin's database schema. A different or
  unreadable schema prevents that host from being ready. It also reports
  shared data permissions and Cursor plugins linked from outside the local
  plugin folder.
- Vault context after compaction uses the host event that can deliver it.
- The Claude Code installer pins the plugin and terminal command to the
  same release and preserves settings permissions.
- Task guides cover installation, verification, vault context, reports,
  and development. A maintained rehearsal retains migration and rollback
  evidence, including failed and incomplete attempts.

The vault experiment remains outside this release. This release makes no
claim of cost savings or improved task acceptance.

## Upgrade

Schema 8 requires a coordinated update of the terminal command and every
active host plugin. Older runtimes cannot open the upgraded database. The
migration preserves historical counts; it does not recalculate them.

Follow [Upgrade to schema 8](../schema-8-upgrade.md). Keep the complete old
data folder and old installers for rollback. Retain any activity recorded
after migration separately if the old data is restored.

Before a live upgrade, review the evidence and approve the intended action.
Use the [release review](../schema-8-release-review.md) to record installation
paths, migration results, and one new session per active host. These live
checks remain pending until performed. Unit tests, synthetic migrations, and
fixture smoke tests do not prove host activation.

Keep the release tag and published artifacts fixed. Review later changes as
a new version and retain the evidence for both versions.
