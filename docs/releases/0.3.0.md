# Agent Efficiency 0.3.0

Version 0.3.0 adds workflow verification and rework accounting, plus an experimental
observe-only Pi adapter. Python 3.11 or newer is required; the runtime remains
standard-library-only.

## Upgrade warning: schema 9

**Stop every writer and back up the complete private data folder before upgrading.**
Update the terminal command, host plugins and source loaders together. Older
runtimes cannot use the upgraded database. Do not reload hosts while tracked jobs
are running. Follow the [coordinated upgrade guide](../schema-9-upgrade.md), including
its rollback procedure. Publishing this release does not migrate your installation.

Synthetic upgrades from actual schema-7 and schema-8 baseline commits preserved
historical records and receipt IDs, retained backups, rejected the old runtime after
migration, recorded new activity, and restored the original backup successfully.

## What's new

- `check --plan`: read-only transitive prerequisite readiness, never target approval.
- Optional private keyed environment selectors for verification identity. These
  identify declared values, not the contents of installed package directories.
- `check --background` and `jobs`: durable managed checks with active-job reuse,
  atomic terminal receipts, timeout handling and cancellation safeguards. A launch
  is not a pass. External host background jobs are not automatically intercepted.
- Opt-in closed structured result summaries distinguish assertion failures,
  invalid baselines/setup, surviving mutations, missing scope and timeouts.
- `evidence explain` and `check --reuse-current`: explicit reuse of current immutable
  receipts, including prerequisite freshness. Ignored/external artifacts are not
  covered by the workspace digest; rerun their comparisons rather than assuming
  they are unchanged.
- Project-owned ordered milestones via `workflow status`; no plan extraction from
  prompts, invented completion percentages or release approval.
- Fixed-code retry/correction ratings, phases and session-linked experiment
  annotations. Failed work stays visible. Potentially overlapping annotation costs
  are never added to existing cohort comparison totals.
- Experimental [Pi observation](../pi.md), advice previews and explicit coverage
  reporting. Unsupported completion/acceptance signals are unavailable, not zero.
- Guard configuration pinning, private action fingerprints and doctor hardening
  described in the [changelog](../../CHANGELOG.md).

## Install

For a new Claude Code installation:

```bash
git clone --branch v0.3.0 https://github.com/agent-efficiency/agent-efficiency.git
cd agent-efficiency
bash install.sh
```

For existing installations, follow the upgrade procedure **before** running the
installer. See [Install](../install.md) for Codex, Cursor and manual installation.
The package and Claude Code/Codex/Cursor manifests all identify version 0.3.0.

## Validation and limits

The [acceptance matrix](../sprints/2026-11-field-acceptance.md) records controls and
scope. Validation includes full Python/Node suites, real worker and privacy
controls, migration/rollback rehearsals, package/wheel checks and host validation.
The Claude validator's missing-icon warning is nonblocking.

No new automatic guard enforcement or bundled advice is enabled by these workflow
features. Local observations and estimates do not establish verified acceptance,
intervention usefulness, billed charges or savings against another host/model.
